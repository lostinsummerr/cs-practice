Git — это программа для отслеживания изменений в коде на вашем компьютере, а GitHub — это сайт и облачный сервис для хранения этого кода и командной работы

git status
Отображает общую сводку по проекту. Показывает текущую ветку. Перечисляет файлы, которые были изменены в рабочей директории, но еще не подготовлены к коммиту. Показывает файлы, добавленные в область подготовки (индекс), которые войдут в следующий коммит. Выводит подсказки о том, какие команды можно ввести дальше.

git diff
Сравнивает содержимое рабочей директории с областью индекса. Показывает неиндексированные изменения — то есть конкретные построчные правки, которые вы внесли в файлы после последнего сохранения, но еще не вызвали для них git add. Если запустить просто git diff, вы увидите разницу во всех измененных файлах проекта.

git diff --staged (или git diff --cached)
Сравнивает проиндексированные изменения с последним коммитом. Показывает то, что уже подготовлено с помощью команды git add и готово отправиться в репозиторий при следующем вызове git commit. Позволяет еще раз проверить свои файлы перед созданием коммита.

Ветка в Git — это указатель на один из коммитов, который представляет собой отдельную линию разработки проекта. По сути, это просто текстовый файл, в котором записан хэш-код конкретного снимка вашей работы, что позволяет изолированно разрабатывать новые функции или исправлять ошибки, не затрагивая основной код.
Когда вы делаете новый коммит, ветка, на которой вы сейчас находитесь, автоматически передвигается вперед. Git создает новый снимок проекта, связывает его с предыдущим коммитом и перемещает указатель текущей ветки на этот свежий коммит. Таким образом, ветка всегда указывает на самую последнюю сохраненную версию в этой линии разработки.
Слияние, или мерж, объединяет изменения из одной ветки в другую. Git берет общую начальную точку двух веток, сравнивает изменения, сделанные в них независимо друг от друга, и совмещает их. Если файлы менялись в разных местах, Git автоматически объединяет код и создает специальный коммит слияния, после чего целевая ветка начинает содержать в себе все наработки из присоединенной ветки. Если же в одной и той же строчке файла были сделаны разные изменения, возникает конфликт слияния, который разработчик должен разрешить вручную.

Главное отличие между командами заключается в их цели и масштабе отображения данных: git log показывает историю коммитов (список авторов, дат и сообщений), git show отображает содержимое одного конкретного объекта (чаще всего коммита со всеми его изменениями), а git diff сравнивает разные состояния кода между собой (например, рабочий каталог с индексом или две ветки).

Разница между базовыми командами:

git log: Показывает хронологический список коммитов (хеш, автор, дата, описание). Нужен, чтобы понять общую историю проекта или найти нужный коммит.

git show: Показывает метаданные и полную разницу изменений для одного конкретного коммита. Нужен, чтобы посмотреть, что именно было сделано в выбранном коммите.

git diff: Показывает построчную разницу между двумя состояниями файлов (незакоммиченные правки, коммиты, ветки). Нужен, чтобы узнать, что изменилось прямо сейчас перед индексацией или коммитом.

Что именно находят git log -S и git blame:

git log -S "строка_поиска": Команда ищет коммиты, в которых количество упоминаний заданной строки изменилось (увеличилось или уменьшилось). Она находит список коммитов, где указанный текст был впервые добавлен или полностью удален. Это нужно, если вы ищете, в каком коммите была добавлена конкретная функция или когда удалили важную переменную. Она игнорирует коммиты, в которых строка просто перемещалась внутри файла без изменения общего количества ее упоминаний.

git blame путь_к_файлу: Команда выводит содержимое файла, где напротив каждой строки указан хэш последнего изменившего её коммита, автор и дата. Она находит конкретного человека и конкретный коммит, после которого строка приняла свой текущий вид. Это нужно, чтобы быстро понять контекст написания строчки кода и найти нужный коммит для чтения его описания.

Чем git restore отличается от git restore --source=... и что произошло бы с вашими правками

Основное отличие заключается в том, откуда именно берутся данные для восстановления. Команда git restore без дополнительных флагов берет версию файла из индекса, а если индекс пуст — из последнего коммита HEAD. Команда git restore с флагом source берет версию файла из конкретно указанного вами места, например, из определенного коммита или другой ветки.
В обоих случаях ваши текущие незакоммиченные правки в рабочей директории будут безвозвратно удалены. Если вы используете обычный git restore, файл вернется к состоянию на момент последней команды git add или последнего коммита. Если вы используете флаг source, файл полностью перезапишется кодом из указанной исторической точки, а все текущие изменения в рабочей директории и индексе будут стерты.

чем это отличается от git reset --hard и почему в опубликованной истории безопаснее revert.

Главное отличие заключается в том, как команды работают с историей: git reset --hard удаляет коммиты из истории ветки, перемещая указатель назад, в то время как git revert создает новый ("обратный") коммит, который отменяет изменения старого, не трогая саму историю.

При работе с git reset --hard вы переписываете историю и жестко стираете все изменения в коде. Эту команду можно использовать только локально, для еще не отправленных в сеть коммитов. Команда git revert сохраняет историю и добавляет новый коммит в конец ветки, поэтому ее безопасно применять как локально, так и в публичных ветках.
